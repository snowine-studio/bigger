# 狂暴放大独立模式设计

## 目标

在现有《再大一点》游戏中加入附件所示的独立互动模式，保留现有剧情、结局、图鉴和本地存档逻辑。玩家可从首页进入该模式，也可随时返回首页。

## 接入方式

采用新增游戏阶段的方式，不增加路由，不新建应用：

- 扩展 `App` 的阶段类型，增加 `rage`。
- 首页增加“狂暴放大”入口，点击进入独立模式。
- 独立模式提供返回首页按钮。
- 新增 `src/components/RageScalingPrototype.tsx`，将该模式的界面、状态和交互封装在组件内，避免继续扩大 `App.tsx` 的职责。

## 界面与交互

组件实现附件中的完整体验：

- 顶部显示文件名和当前缩放比例。
- 左侧甲方聊天内容随缩放阶段变化，并显示越界警告。
- 中央海报中的产品逐渐消失，Logo 持续放大，在后期出现色差故障、界面抖动和压缩变形。
- 底部普通滑块支持 30%–100% 缩放。
- 按住狂暴按钮时，从当前比例指数增长；松手后保留当前比例，再次按住可继续。
- 达到 10000% 后进入“超验大师”结局，停止音频和动画，并可重新体验。
- 返回按钮在各阶段可用；奇点结局中也保留退出能力。

使用 Pointer Events 统一鼠标和触屏操作，按钮支持键盘长按。指针松开、移出、取消以及组件卸载都必须停止蓄力。操作期间禁止长按选中文字和弹出上下文菜单。

## 动画与状态

组件维护缩放值、是否蓄力、是否到达奇点三个核心状态，并由缩放值推导故障、坍塌、台词和警告等表现。

蓄力使用 `requestAnimationFrame`，根据相邻帧的真实时间差计算指数增长，避免 60 Hz、120 Hz 屏幕上的速度差异。每帧取消或组件卸载时释放动画句柄，避免重复循环。

移动端采用可收缩侧栏和可换行控制区，确保画布、入口和主要按钮在窄屏上仍可操作。尊重 `prefers-reduced-motion`：保留缩放和阶段反馈，降低非必要的抖动与位移动画。

## 音频

在现有 `src/game/audio.ts` 中增加狂暴模式的持续音控制，复用现有 AudioContext、主音量和静音状态：

- 首次按住按钮后创建或恢复音频。
- 随缩放比例调整频率与音量。
- 松手、到达奇点、返回首页及组件卸载时停止或静音持续音。
- 浏览器不支持或拒绝音频启动时静默降级，不阻断视觉交互。

## 错误处理与资源清理

- 所有动画和音频资源均在组件清理函数中释放。
- 重复按下不会创建多个动画循环或音频振荡器。
- 奇点状态只触发一次，重开后恢复 30% 和初始界面。
- 本地存储、剧情阶段数据及既有音频背景音乐逻辑保持不变。

## 验证

- 运行 TypeScript 构建和 ESLint 检查。
- 在浏览器验证首页进入、返回、滑块、鼠标／触屏／键盘长按、松手暂停、继续蓄力、10000% 结局和重开。
- 验证反复进入退出后无残留声音或动画。
- 检查桌面与窄屏布局，以及静音和减少动态效果设置。
- 确认现有剧情入口与游戏流程未受影响。
